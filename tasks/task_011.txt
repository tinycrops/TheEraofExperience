# Task ID: 11
# Title: Implement Persistent Storage for VectorMemory using HNSW or SQLite
# Status: pending
# Dependencies: None
# Priority: high
# Description: Enhance the VectorMemory module to support disk-based persistent storage of embeddings and metadata using either HNSW or SQLite, while maintaining the existing API and ensuring efficient similarity search capabilities.
# Details:
Extend the VectorMemory module to store vector embeddings and associated metadata on disk rather than only in memory. This implementation should:

1. Create a new storage backend that uses either:
   - HNSW (Hierarchical Navigable Small World) for efficient approximate nearest neighbor search
   - SQLite with appropriate indexing for vector similarity search

2. Maintain the existing API methods:
   - `addMemory(text, embedding, metadata)` - Should now persist to disk
   - `querySimilar(embedding, limit)` - Should query from persistent storage

3. Implement a configuration mechanism to specify storage location, index parameters, and other relevant settings

4. Add a migration utility to transfer existing in-memory data to the new persistent storage

5. Ensure thread-safety for concurrent read/write operations

6. Implement proper resource management (connection pooling if using SQLite, index loading/unloading for HNSW)

7. Add performance optimizations:
   - Caching frequently accessed vectors
   - Batch operations for bulk imports
   - Background indexing for large datasets

8. Handle edge cases:
   - Graceful recovery from corrupted storage
   - Automatic reindexing when needed
   - Versioning for future compatibility

Dependencies to consider:
- For HNSW: hnswlib, faiss, or similar libraries
- For SQLite: sqlite3 with appropriate extensions for vector operations

Performance requirements:
- Should support at least 1M vectors with sub-second query times
- Minimal memory footprint regardless of dataset size

# Test Strategy:
Testing should verify both functional correctness and performance characteristics:

1. Unit Tests:
   - Test persistence by adding vectors, restarting the service, and verifying they can be retrieved
   - Verify that metadata is correctly stored and retrieved with vectors
   - Test edge cases: empty database, very large vectors, malformed inputs
   - Verify API compatibility with existing code that uses VectorMemory

2. Integration Tests:
   - Test the migration utility with various dataset sizes
   - Verify that existing application flows work with the new storage backend

3. Performance Tests:
   - Benchmark query times for different dataset sizes (10K, 100K, 1M vectors)
   - Measure memory usage during operation
   - Test concurrent read/write operations and verify correctness
   - Compare performance between HNSW and SQLite implementations

4. Stress Tests:
   - Test with very large datasets to verify scaling capabilities
   - Simulate disk failures or corruption and verify recovery

5. Specific Test Cases:
   - Add 1000 vectors, restart, verify all are retrievable
   - Perform similarity search and compare results with in-memory implementation
   - Verify that updates to existing vectors are correctly persisted
   - Test with various embedding dimensions (128, 384, 768, 1536)
   - Verify that deleting vectors removes them from persistent storage
